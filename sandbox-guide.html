⚙️ 2. The 3 Core Execution Models (Trade-offs & Comparison)

Client-Side Micro-Runner (Used Here)

Model A: In-Browser Simulated Engine

  • How it Works: Pure JavaScript parses Console.WriteLine, simulates MSIL Roslyn compile output, and renders terminal logs.
  • Latency: < 15ms (Instantaneous feedback).
  • Hosting Cost: $0 / month (Runs on static CDNs like Netlify, GitHub Pages, Vercel).
  • Best For: Architectural portfolios, rapid syntax exploration, zero-budget serverless sites.
WebAssembly (WASM)

Model B: Blazor / Roslyn In-Browser WASM

  • How it Works: Downloads the official dotnet.wasm runtime and Roslyn compiler directly into the browser. Real C# executes on the client's CPU!
  • Latency: Cold boot download (~12MB), then ~80ms per compile.
  • Hosting Cost: $0 / month (Static WASM assets).
  • Best For: High-fidelity offline playgrounds, real C# compilers without server management.
Enterprise Cloud Sandbox

Model C: Docker / gVisor Microservice API

  • How it Works: ASP.NET Core Web API dispatches code to ephemeral Linux containers with cgroups (64MB RAM limit, 3s execution timeout, no network).
  • Latency: ~400ms – 1.2s (Network round-trip + process spin-up).
  • Hosting Cost: Requires Azure Container Apps / AWS ECS ($15–$50/mo).
  • Best For: Full NuGet package support, LeetCode-style multi-file test suites.

Step 3: Handle Developer Ergonomics (Tab Indent & Ctrl + Enter)

Native HTML textareas lose focus when pressing the Tab key. Intercept the keydown event to insert 4 spaces at the cursor, and listen for Ctrl + Enter (or Cmd + Enter) to trigger execution:

textarea.addEventListener('keydown', function(e) {
    if (e.key === 'Tab') {
        e.preventDefault();
        const start = this.selectionStart;
        const end = this.selectionEnd;
        this.value = this.value.substring(0, start) + "    " + this.value.substring(end);
        this.selectionStart = this.selectionEnd = start + 4;
    }
    if ((e.ctrlKey || e.metaKey) && e.key === 'Enter') {
        runSandboxCode();
    }
});

Step 5: Enterprise Backend Runner API (ASP.NET Core Minimal API + Docker)

If you need real cloud execution with external NuGet packages, create a secure sandboxed Minimal API endpoint in ASP.NET Core that spawns an ephemeral Docker container with tight resource bounds:

// Program.cs - ASP.NET Core Minimal API Sandbox Endpoint
app.MapPost("/api/sandbox/execute", async ([FromBody] CodeRequest req) => {
    // 1. AST Validation using Roslyn to block forbidden namespaces
    var syntaxTree = CSharpSyntaxTree.ParseText(req.SourceCode);
    if (HasForbiddenImports(syntaxTree)) {
        return Results.BadRequest(new { error = "Unauthorized namespace detected (System.IO, System.Net.Sockets)" });
    }

    // 2. Execute inside ephemeral container with 3s timeout & 64MB memory limit
    using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(3));
    var result = await DockerSandboxRunner.RunIsolatedAsync(req.SourceCode, cts.Token);
    
    return Results.Ok(new { stdout = result.Output, exitCode = result.ExitCode });
});

🔒 4. Lead / Architect Interview Question: Sandbox Security & Isolation

Interviewer asks: "If you build an online code execution runner like LeetCode or .NET Fiddle, how do you prevent users from crashing your servers with infinite loops, fork bombs, or malicious disk access (File.Delete('/etc/passwd'))?"

Layer 1: Pre-Compile AST Inspection

Use Roslyn's CSharpSyntaxTree to inspect the Abstract Syntax Tree before compiling. Ban identifiers like System.Diagnostics.Process, System.IO.File, System.Reflection.Emit, and unsafe pointers.

Layer 2: Kernel cgroups & CPU Quotas

Use Linux Control Groups (cgroups v2) to strictly limit CPU usage to 0.5 cores and RAM to 64MB. If an algorithm allocates memory greedily, the Linux OOM Killer terminates the process instantly without affecting neighbors.

Layer 3: Network & Syscall Isolation

Run the container with --network none and a read-only root filesystem. Use gVisor (runsc) or seccomp to intercept and block arbitrary Linux syscalls, preventing container escapes.

Layer 4: Execution Watchdogs

Attach a CancellationTokenSource with a strict 3,000ms deadline. If the code enters an infinite while(true) loop, the watchdog issues a SIGKILL and returns a clean "Time Limit Exceeded" status.
